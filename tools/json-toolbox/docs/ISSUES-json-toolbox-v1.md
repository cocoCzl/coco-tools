# JSON 工具箱 V1 开发任务

来源：[JSON 工具箱 V1 PRD](./PRD-json-toolbox-v1.md)

所有任务均为 AFK，可以在无需额外产品决策的情况下独立领取。任务按依赖顺序排列；每项都应在同一变更中交付可验证的用户行为及对应自动化测试。

当前代码已经覆盖 17 项任务的主要功能，但仍有真实浏览器交互、Worker 集成、离线、内存和 GitHub Release 验收未完成。因此本文件暂时保留，待 V1 正式发布后再删除或归档。

状态含义：

- **完成**：实现及该任务的验收证据均已具备。
- **已实现，待验收**：功能已经存在，但仍缺真实浏览器或专项测试证据。
- **部分完成**：任务仍有明确交付项未完成。

## Issue 1：搭建可安装的 JSON 工具箱扩展骨架

**Type:** AFK
**Status:** 完成
**User stories covered:** 1、35

### What to build

建立独立、可构建、可测试和可加载的 JSON 工具箱 Chrome 扩展。扩展采用 Manifest V3、TypeScript 与浏览器原生 Web 技术；点击工具栏图标后打开独立的 JSON 工作台标签页。此任务只交付最小可运行纵向路径，不加入具体 JSON 工具功能。

### Acceptance criteria

- [x] JSON 工具箱作为独立 workspace 安装依赖、构建和测试，不依赖 TSP CVT 的运行时代码。
- [x] 生产构建生成可由 Chrome“加载已解压的扩展程序”加载的 Manifest V3 目录。
- [x] 点击工具栏图标会打开一个独立工作台标签页；重复点击优先聚焦已打开的工作台，不无限创建重复标签页。
- [x] 工作台显示产品名称和可识别的最小空状态，且没有工具栏弹窗、Side Panel 或网页内容脚本。
- [x] 建立行为导向的测试命令，并至少覆盖构建入口和工作台打开逻辑。
- [x] Manifest 不申请站点访问或剪贴板读取权限。

### Blocked by

None - can start immediately.

## Issue 3：交付严格、无损的 JSON 格式化与错误定位

**Type:** AFK
**Status:** 完成
**User stories covered:** 4、6、7、8、9

### What to build

交付可在格式化页签中使用的严格 JSON 校验与无损格式化能力。格式化只能调整字符串外部空白，必须保留字段顺序、数字字面量、字符串转义及其他有效标记文本，并检测重复字段。

### Acceptance criteria

- [x] 点击格式化后，合法严格 JSON 使用默认 2 空格缩进输出，原输入保持不变。
- [x] `9007199254740993`、`1.00`、`1e3` 和 Unicode 转义在格式化后保持原始标记写法。
- [x] 字段顺序及字符串内部的空白、转义和换行语义保持不变。
- [x] 注释、单引号、未加引号字段、尾随逗号及其他非标准 JSON 被拒绝。
- [x] 同一对象内重复字段被拒绝，不静默保留最后一个值。
- [x] 错误状态显示准确行号、列号和可理解的原因，并清空旧输出。
- [x] 行为测试覆盖嵌套对象、数组、空对象、空数组、标记保留、重复字段和典型语法错误。

### Blocked by

- Issue 2

- [x] 压缩与格式化使用同一套严格校验和重复字段规则。
- [x] 格式化与压缩发生错误时均清空旧输出并显示相同质量的定位信息。
- [ ] 自动化测试覆盖三种缩进、压缩、偏好持久化和格式化/压缩往返行为。

## Issue 6：交付 URL 查询参数转 JSON

**Type:** AFK
**Status:** 完成
**User stories covered:** 15、16、17、18

### What to build

在 URL 参数页签交付从完整 URL、带问号查询字符串或纯查询字符串生成 JSON 的流程。输出只表达查询参数，所有值保持字符串语义。

### Acceptance criteria

- [x] 完整 URL、`?a=1&b=2` 和 `a=1&b=2` 产生相同 JSON 结果。
- [x] 路径和 `#fragment` 不出现在输出 JSON 中。
- [x] `code=001&enabled=true` 输出为字符串值，不推断数字或布尔类型。
- [x] `tag=a&tag=b` 输出为字符串数组，并保持值出现顺序。
- [x] `+` 解码为空格，`%2B` 解码为加号，UTF-8 中文正确解码。
- [x] 非法或不完整百分号编码被拒绝，旧输出被清空并显示明确错误。
- [x] 自动化测试覆盖三种输入形式、重复参数、空值、特殊字符和非法编码。

## Issue 9：完善 Java 数组合并与安全类型推断

**Type:** AFK
**Status:** 完成
**User stories covered:** 22、23、24

### What to build

扩展 Java 数据类生成，使其支持根对象数组、字段数组、跨样例字段合并、空值和安全数字类型提升，并在无法可靠推断时生成明确警告。

### Acceptance criteria

- [x] 根对象数组扫描所有元素并合并字段，不遗漏后续元素新增字段。
- [x] 根数组混入非对象元素时停止生成并报告不一致位置。
- [x] 同类型数组生成 `List<T>`，对象数组合并元素字段并生成嵌套元素类。
- [x] 数字按 `Integer → Long → BigInteger` 安全提升；整数与小数混合使用 `BigDecimal`。
- [x] 空字段数组生成 `List<Object>` 并警告；空根数组不生成结果。
- [x] 全部为 `null` 的字段使用 `Object` 并警告；`null` 与具体类型并存时采用具体类型。
- [x] 互不兼容的具体类型及混合数组使用 `Object` 或 `List<Object>` 并警告。
- [x] 字符串不自动推断日期、UUID 或枚举。
- [x] 自动化测试覆盖全部提升、合并、空值、混合类型和警告场景。

## Issue 12：增加 UTF-8 文件导入与大文件确认流程

**Type:** AFK
**Status:** 已实现，待浏览器验收
**User stories covered:** 28、31

### What to build

为各工具增加本地 `.json` 和 `.txt` 文件导入，处理 UTF-8 与 UTF-8 BOM，并在超过 20 MB 时要求用户确认后再载入。

- [ ] UTF-8 和 UTF-8 BOM 文件正确读取，BOM 不出现在输入文本中。

- [ ] 取消导入不会改变原输入、输出或错误状态。
- [ ] 文件内容只存在本地内存中，不建立最近文件或历史记录。
- [ ] 自动化测试覆盖 UTF-8、BOM、不支持类型、大文件确认和取消流程。

## Issue 13：增加大任务 Worker、取消和旧任务隔离

**Type:** AFK
**Status:** 已实现，待集成测试
**User stories covered:** 31

### What to build

让超过 1 MB 的转换任务通过按需 Worker 执行，同时保持与小任务相同的结果和错误语义。任务可以取消，旧任务不能覆盖新任务结果，结束后 Worker 必须销毁。

### Acceptance criteria

- [ ] 小于等于 1 MB 的任务保持低开销直接执行，超过 1 MB 的任务通过按需 Worker 执行。
- [ ] Worker 结果、警告和错误与同一输入的直接执行结果一致。
- [ ] 执行期间界面保持可交互，并显示进行中状态和取消操作。
- [ ] 用户取消后不提交部分或旧结果，状态恢复为可再次执行。
- [ ] 重新执行、切换页签或关闭工作台会终止相关旧任务。
- [ ] 较早启动的任务即使较晚完成，也不能覆盖较新的任务结果。
- [ ] Worker 在完成、失败或取消后销毁，不保持空闲后台线程。
- [ ] 自动化测试覆盖阈值、结果一致性、取消、竞态和销毁行为。
